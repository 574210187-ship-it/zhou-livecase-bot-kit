# 人看字段与证据硬门禁

## 目的

飞书表格是业务人员直接阅读的生产结果，不是调试日志、队列或模型中间态。任何写入计划在进入私有 runner 前，都必须通过 `validate-visible`；独立 auditor 仍要在写后再次读表核验。

## 必填人看字段

- 故事标题
- 故事概要
- 主方向
- 次方向
- 单麦作用及依据
- 可借鉴元素
- 禁借元素

这些字段必须是自然、具体、可直接理解的中文。标题为 6 至 60 个字符，不含标点；说明必须说清人物、事实、冲突或可借鉴方法，不能只有分类标签。

## 明确禁止

- 把 `blocked_model`、`resume_execution_result`、`CONTENT_REVIEW`、`None`、`null`、`TODO`、调试栈等内部信息写进业务字段；
- 写“普通案例麦”“待处理”“内部标识”等没有具体解释的模板词；
- 把 JSON、对象路径、附件 URI、COS 地址或公网 URL 倾倒进业务说明字段；
- 用模型猜测补充原稿没有的金额、年龄、年限、比例、次数或人物关系；
- 引文不是源稿的逐字子串，或 claim 中的数字事实没有在同条展示引文中出现；
- 把别的录屏、别的来源记录或旧批次结果串到当前记录；
- 用“已上传”“请求成功”“生成了 ZIP”替代四方读回完成。

## 机器门禁

```bash
PYTHONPATH=src python3 -m zhou_livecase.external_bot_entrypoint \
  validate-visible --input visible_payload.json
```

返回 `passed=false` 时，必须只返工对应边界或字段；不得带错写表，也不得通过修改词表来制造绿灯。机器门禁只保证确定性底线，语义是否正确仍由独立 auditor 按源稿和目标表读回核验。
