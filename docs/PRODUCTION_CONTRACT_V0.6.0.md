# 生产合同 v0.6.0

## 角色

- 外部 Bot：实时发现、结构化分析、局部返工和编排；不直接持有生产写密钥。
- 私有 runner：唯一远端写入者，按阶段幂等写入并立即读回。
- 独立 auditor：使用分离的只读身份，全分页核验目标系统。
- 用户：只负责提供最小平台授权和真正需要真人裁定的 review，不负责搬运长回复。

## 候选与记录终态

候选必须来自本轮全分页实时来源快照，覆盖当日新增、最新批次和历史未终态。每条记录最终只能进入：

- `complete`：四方读回和独立审计通过；
- `closed_no_accept`：无可发布边界，源表终态读回通过；
- `duplicate_processed`：明确主记录和去重证据，源表终态读回通过；
- `review_pending`：需要真实人工裁定；
- 精确的 `blocked_*` / `failed_*`：只阻断本条并写明下一动作。

一个失败不能停止其余可处理记录。外部权限缺失也只能阻断实际需要该权限的阶段。

## 写入顺序

`storage → case → q50 → source`。源表关闭前必须确认前序目标存在且归属正确。任何重试复用同一幂等键和 generation；内容变化必须递增 generation 并绑定新 analysis SHA。

## 内容门禁

写入前同时满足：来源身份一致、人看字段自然中文、标题规则、证据逐字命中、claim 数字事实由同条展示引文支持、review 未被代签、没有内部码/JSON/存储地址污染业务字段。

## 两条执行路径

- A：Bot 在单窗口内生成结构化分析；
- B：Bot 用可见浏览器自动化委托普通 ChatGPT，每条结果下载验真并删除已验收会话。

两条路径先用同等小样测试。路线选择顺序固定为：质量和独立审计通过 → 耗时更短 → 宿主真实报告 token 更少 → 重试更少。未报告 token 记未知，不能编造。

## 发布状态

公开程序与无密发布包只能证明合同和门禁可用。某个 Bot 的生产接通必须另外取得：能力 preflight、私有入口日志、启动配置、首条实时业务四方读回和独立审计。缺任一项均为“已部署待验收”。
