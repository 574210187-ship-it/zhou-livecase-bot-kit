# v0.4.2 兼容迁移

## 目的

把本仓库的不可变快照、统一阶段回执、独立审计和返工合同接到已由真实业务验证的 v0.4.2 生产实现；不另起环境、不重写四个写入阶段、不复制敏感配置。

## 可复用资产

| 既有资产 | 继续负责 | 新仓库增加 |
| --- | --- | --- |
| 私有生产环境 | 受保护运行时与加密凭据绑定 | 提交/ZIP/环境三方版本锚定 |
| COS 适配器 | 路径约束、上传、HEAD、下载 SHA、禁止删除 | 标准化 `StageReceipt` |
| 飞书写入适配器 | 案例库、Q50、源表的幂等写入与读回 | `SourceSnapshot` 绑定、generation 回执键 |
| 既有四方验收 | 目标系统真实读回 | 与独立 auditor 的 shadow 对照 |
| 既有每日 worker | 每日唯一业务入口 | 兼容入口切换，禁止新增第二个 worker |

## 已实现的薄桥接合同

`zhou_livecase.compat.v042.V042StageBridge` 是唯一允许的过渡桥。私有环境为
`STORAGE_WRITE → CASE_WRITE → Q50_WRITE → SOURCE_WRITE` 分别注入既有执行器；桥接层只
接受 `verified=true`、同一 `run_id`/`record_id` 和匹配阶段的既有读回，再转换为可移植
`zhou-stage-receipt-v1`。缺少适配器、阶段错配、跨记录回执或未验证读回都会在后续阶段
开始前失败。

桥接模块不读取密钥、不接受 AI 任意回调、不保存表 ID 或对象路径；真实 COS 与飞书操作仍
完全由既有 v0.4.2 私有适配器负责。

## 最小实施顺序

1. **版本锚定**：在既有私有环境只读当前 v0.4.2 版本、安装位置和非敏感 readiness；将其与本仓库的固定提交、发布 ZIP SHA 写入一次部署清单。失败即停止，不新建环境。
2. **薄包装**：为“存储、案例库、Q50、源表”分别建立调用既有适配器的 wrapper。wrapper 只负责输入合同校验、调用、标准化 `StageReceipt` 和读回；不重新实现 SDK/CLI，不接触或打印密钥。
3. **读写分界**：runner 进程只通过四个 wrapper 写入；auditor 通过只读 reader 重新读取目标系统，不能导入 runner 状态或调用 wrapper。首期可共用同一私有环境，但必须是不同进程且 auditor 没有写入口；平台支持时再升级为独立身份。
4. **零写 shadow audit**：任选一个已经四方完成的历史样本，以新 auditor 全量读取并和既有完成读回对账。任何字段、存储 SHA、Q50 关联或源表终态差异都先修兼容层，不进入新写。
5. **实时金丝雀**：从新鲜全分页 `SourceSnapshot` 中选择一条未终态记录。由 wrapper 依序存储→案例库→Q50→源表；各阶段写后读回；新 auditor 独立通过才结束。
6. **单 worker 切换**：只修改既有每日 worker 的入口到兼容层。读回确认没有第二个业务 worker；下一次自然任务必须产生真实开始、结果或问题事件及目标系统证据。

## 禁止项

- 不复制、导出或上传任何 COS/飞书密钥、Webhook、Cookie 或真实运行状态。
- 不同时启用旧/new 两个写入 worker。
- 不用历史回执、离线测试、HTTP 成功或 shadow audit 宣称金丝雀完成。
- 不为“验证”重写已经完成的历史记录。
- 不在 wrapper 内改变既有字段映射或 COS 路径；确需业务变更时，先升级合同和反例回归。

## 通过条件

仅当六步均有运行入口日志和目标系统读回时，兼容层可标记为“已由真实业务验证”。在此前，本仓库始终是“草案”或“已部署待验收”。
