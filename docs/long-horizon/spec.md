# Task Spec

## Objective

- 发布一套无密、可公开下载、可由 Grok Bot 与 Muse Bot 独立执行的直播稿拆解生产包。
- 同一套包支持两条路径：A 单窗口内联分析；B 主控 Bot 委派普通 ChatGPT 网页聊天逐稿分析。
- 两条路径最终都只能把结构化分析交给确定性 runner；真实 COS、案例库、Q50、源表写入必须经唯一写入口和独立 auditor。

## User Outcome

- 用户只需向 Grok 或 Muse 发送一条总启动令，Bot 即可读取实时源表、完成分析、门禁、写入、逐 ID 读回、审计和局部返工。
- 如果缺飞书、COS 或浏览器授权，Bot 只列最小授权项并停在对应记录；不得索取或展示密钥，不得猜表格字段。
- 表格文本必须是普通人可直接看懂的中文业务内容，禁止内部码、调试词、占位话、笼统完成话和不受原文支持的事实。

## In Scope

- 外部 Bot 能力预检、授权清单与 fail-closed 路由。
- A/B 两条分析路径的统一输入/输出合同。
- 中文可读性、证据支撑、来源身份、字段完整性和禁止内部码门禁。
- 普通 ChatGPT 委派会话账本、结果下载校验和完成后删除回执。
- 确定性 runner、稳定幂等键、四阶段顺序写入与逐 ID 读回。
- 独立只读 auditor、最小 ReworkOrder 和历史错误反例回归。
- Grok/Muse 通用总启动令、路径对比测试和选路报告。
- 无密发布 ZIP、GitHub 公共仓库、固定提交与下载链接。

## Out Of Scope

- 公开仓库保存真实 app token、COS 密钥、Webhook、cookie、表 ID、bucket/prefix、业务源稿或运行回执。
- AI 直接持有生产凭据或绕过 runner 直写外部系统。
- 为测试制造真实业务批次、重复写历史终态、代替人工签署 review。
- 在 Bot 不具备受支持浏览器控制时调用隐藏应用接口冒充 ChatGPT 委派路径。

## Acceptance Criteria

1. `preflight` 能分别判定 Grok/Muse 对 A/B 路径的可执行性，并输出最小缺失授权。
2. A/B 两条路径输出同一分析合同；不合格输出无法进入 write plan。
3. 人看字段门禁能阻断内部码、模板占位、空泛标题、证据外事实和不可读文本。
4. 委派路径缺 conversation ID、下载 SHA 或删除后不存在回执时不得收口。
5. 完成态仍严格要求 COS/案例库/Q50/源表四方逐 ID 读回和独立 auditor。
6. 历史错误全部形成匿名回归；全量测试、发布扫描和 ZIP CRC/SHA 通过。
7. 公共 GitHub 仓库可匿名下载；文档含直接可复制的 Grok/Muse 总启动令和两个路径测试要求。
8. 公共发布不包含任何真实凭据、真实表 ID、真实业务数据或本机绝对路径。

## Constraints

- Python 3.11+、标准库优先；不得增加不必要依赖。
- 复用现有 runner/auditor，不重写成熟生产适配器。
- 私有授权在部署环境注入；公开包只写变量名和授权流程。
- 任何 Bot 自述、线程更新时间、HTTP 成功、单表写入、报告或测试都不能替代目标系统读回。

## Open Questions

- Grok/Muse 的具体工具名称由各自宿主决定；公开包以能力声明合同适配，不硬编码供应商私有接口。
- B 路径只有在宿主提供受支持的可见 UI 自动化、文件上传/下载和会话删除能力时可用，否则只测试 A 路径并如实记录能力缺口。
